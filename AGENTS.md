# Forma Studio

Forma Studio is a single-user local web app for turning a brand kit and a marketing brief into a square animated ad. A designer can explore several directions with the same brand assets, choose one, and review a working creative in the browser.

## Creative workflow

1. **Upload the brand kit.** Drag in files or a folder. The app preserves nested paths so the creative can reference supplied logos, fonts, images, and other assets.
2. **Develop the brief.** Enter a scenario and visual style, or ask the selected model to draft them. The style picker proposes three distinct visual directions with square SVG previews. The user can choose a direction and edit its description before generating the ad.
3. **Build the creative.** The model generates one responsive HTML document that recomposes for every selected format (1:1, 4:5, 9:16, 16:9, 5:4, 1.91:1) and plays a deterministic `window.renderFrame(t)` timeline of the chosen length. With an OpenRouter key it can generate and self-check images and video clips. The runtime provides Three.js and its addons, GSAP, and Lottie alongside browser-native SVG and Canvas.
4. **Review the result.** The app scales the composition into a square, sandboxed preview on a separate origin. Each build saves its HTML and assets locally, and the browser can restore the last preview.

## Generation modes

Claude uses the Claude Agent SDK. Codex uses a locally installed Codex CLI. The interface supports model and reasoning-effort selection, with API-key or local subscription authentication. During live generation, the provider can receive the brief and brand material the model reads. Demo mode uses a bundled animation to exercise uploads and preview rendering without a model call.

## Working on the app

- Start with `public/` for upload interactions, brief editing, style selection, and preview controls.
- Use `server.mjs` for request handling, project storage, and serving preview assets. `generator.mjs` and `codex.mjs` handle the respective provider integrations.
- Look in `creative.mjs` for shared creative instructions and style generation, `motion.mjs` for formats, the in-creative `window.FORMA` runtime and the postMessage playback controller, `media.mjs` for OpenRouter image/video tools (`media-mcp.mjs` exposes them to Codex over stdio MCP), and `models.mjs` for model choices.
- Use Node.js 22.9 or newer. From this directory, run `npm ci` on first setup, then `npm start`. Open `http://127.0.0.1:4317`. The preview server defaults to port 4318.
- `render.mjs` renders built previews and finals in headless Chrome (puppeteer-core, system Chrome or `FORMA_CHROME`) into contact sheets. `POST /api/campaigns/:id/review` lets a model look at them and saves its notes as a `review` history entry; the UI applies them as a normal revision (`reviewId` marks the look applied). Final notes are applied once automatically; preview notes only when `setup.review.autoApplyPreview` is on. The renderer also collects what the browser reports (script and console errors, failed loads, a creative that never got ready) and flags frames that came out one flat colour; it shoots text close-ups at full size. These go to the model as `render_problems`, and after a build their notes are applied once even when auto-apply is off. Sheets hold at most four tiles so the model sees them unscaled. `assets/review/` is never pulled by `sync.down` (the preview origin reads through to R2 when a sheet is shown).
- The v2 runtime (`motion.mjs`) offers `FORMA.findSurface(img)` (corners of a flat #00FF00 surface in a displayed picture) and `FORMA.pin(el, quad)` (a matrix3d perspective pin) for interfaces on screens inside photographs.
- Campaigns can be archived (`POST /api/campaigns/:id/archive`, stored as entry status `archived`); `GET /api/campaigns` hides them unless `archived=1`. List items are cached per campaign version.
- Brand notes (`BRAND-NOTES.md`, written by `brands.mjs`) are a brand file that every step receives in its message; their "Client decisions" override the brief.
- `pricing.mjs` holds API list prices for cost estimates. The revision chat lives in `POST /api/history/:id/revise`: Claude edits a temp working copy (`generator.mjs` `revise`), and Codex returns full HTML.
- Storage goes through `store/index.mjs`, selected by `FORMA_STORE`: `file` (default; one JSON per entry in `DATA_DIR/history/`, files on disk), `supabase` (Postgres entries + asset index + runs, all bytes and logs in Cloudflare R2), or `memory` (test-only fake of the supabase driver). `history.mjs` re-exports `store.history`, and **every history call is async**. `jobs.mjs` holds the live journal and flushes events to `runs`/`run_events` in cloud mode.
- Cloud sync happens at the edges, not in writers: `store.sync.down(project)` before a model job, `store.sync.up(project)` after it, and the entry is recorded only after the upload. The preview origin reads through to R2 on a cache miss. Local `DATA_DIR/<project>/<rel>` maps to the R2 key `projects/<project>/<rel>`; logs live at `logs/<entryId>.json`.
- Campaigns hold style variants (`variants[]`, `activeVariant`) that share one scenario. `upgradeCampaign` converts old single-style docs.
- Schema changes go in a new file in `supabase/migrations/`; bump `schema_meta.forma_schema` only for breaking changes. `scripts/migrate-to-cloud.mjs` / `scripts/pull-from-cloud.mjs` (core in `scripts/lib/cloud-migrate.mjs`) move data between local and cloud; both are idempotent, and neither deletes local files. Owner-facing steps live in `docs/cloud-runbook.md`.
- Keep credentials in the environment or the ignored `.env` file. Generated projects live under `data/` by default. Set `DATA_DIR` to place them on a persistent volume when running in a container.
- **Client dashboard (studio side).** The client dashboard lives in a separate repo (toggle-concepts; its `docs/contract.md` is the contract). Forma reads its tables (`client_accounts`, `brand_questionnaires`, `campaign_requests`, `deliveries`, `delivery_comments`, `client_events`…) through `store.db()` and changes statuses only through `client_questionnaire_transition` / `client_campaign_transition`. `studio.mjs` holds the studio half of the dashboard's planners (keep them in step with its `lib/state-machine.ts`), the inbox builder and `/api/studio/*`. The Clients page (`public/clients.js`, route `/clients`) shows what waits for the studio. It works only with `FORMA_STORE=supabase` and the migration `20261120000001_client_dashboard.sql` applied.
- **Questionnaire moderation.** `shared/questionnaire-schema.mjs` is generated from the dashboard's `questionnaire/schema.ts` by `node scripts/sync-questionnaire-schema.mjs` (Node 22.13+); never edit it by hand. `test/studio-questionnaire.test.mjs` fails when the copy drifts (if toggle-concepts sits next to forma). `studio-questionnaire.mjs` turns the stored state into the studio's view; `/clients/questionnaires/<id>` shows it, sends follow-up questions (notes first, then the unlock, rolled back on failure) and approves (brand names editable). Client files stream from R2 through `/api/studio/files/:id`.
- **Brands from questionnaires.** Approval starts `studio-brand.mjs` in the background (retry: `POST /api/studio/questionnaires/:id/brands`). One Forma brand per `client_brands` row, with the **same id**, so a retry finds what was made; `client_brands.forma_brand_id` is set after. The brand gets the scope's `client_files` (zips unpacked by `zip.mjs`, node:zlib only, one top folder flattened, junk dropped; files over 128 MB are not copied and are listed in the manifest's `origin.skipped` for the brand page) and `BRAND-NOTES.md` holding only the hard answers as client decisions (`clientDecisions`). The questionnaire itself is not a brand file: answers reach the brand only through `clientDecisions`. Notes holding only decisions count as not written (`notesHaveBody`), so the writer still runs and keeps them. `refs` files belong to campaigns, not brands.
- **Brand book board.** `brand-board.mjs` + `public/brand-board.js`: colours found in the brand's text files, logos, typefaces (FontFace specimens), pictures, video, PDFs (browser viewer), files not copied from the client. For people only: no step, prompt or model reads it. Files are served by version and path from `/api/brands/:id/file?v=&name=` (Range for video, sandboxed SVG).
- **Read Figma.** `figma.mjs` reads a Figma file through the REST API with `FIGMA_TOKEN` (the studio's account; Figma rates the content and image endpoints by the token's seat and by the plan of the team holding the file, so a file in a free team gets a few reads a month and must be duplicated into the studio's team). One read = the file at depth 2 (or the linked page/frame), one call for style values, one images call per scale; frames land as `figma/<file>/<page>/<frame>.png`, styles as `figma/<file>/styles.json`, recorded in `brand.figma`; a re-read of the same file replaces its folder (`addFigmaFiles`). Brand page: `POST /api/brands/:id/figma`; approval reads up to 3 Figma links found in that brand's answers when the token is set. Afterwards `notesAfterNewFiles` writes the notes if there are none yet, otherwise they show as outdated.
- **Campaign requests.** `studio-campaign.mjs`: `/clients/campaigns/<id>` shows the request (setup, brief, references, rounds); Accept and Cancel go through `client_campaign_transition`. Accept makes the Forma campaign first with `createClientCampaign` (campaigns.mjs; **campaign id = request id**, so a retry finds it), the client's brand at its latest version, the studio's model settings, and the `refs` files of that account under `assets/client-references/`; then moves the status with `forma_campaign_id`. `campaign.client` holds the request, the cleaned brief and `briefText`, which the script step sends as `brief` (next to the studio's `notes`, which win). `public/client-banner.js` shows the request on the campaign page with its live status.
- **Directions to the client.** Sent by hand from the campaign page ("Send directions…" in the client banner, `public/send-directions.js`) while the request is `in_progress`. `directionsOf` lists every variant with a preview (the dashboard's `toGalleryCampaign`); `buildDirectionsSnapshot` takes exactly three in the picked order with the studio's client wording (`clientTitle` strips Native/World/Bold), an optional note (≤600) and the preview path (`/p/<project>/<rev>.html`, served to the client from R2); `sendDirections` checks status and version and calls `send_directions` (`/api/studio/campaigns/:id/directions`).
- **The client's answer.** "Client’s answer…" in the banner once a round is answered (`public/client-response.js`): the decision, the sent comments (drafts stay the client's) by direction, pins drawn over the same preview at the comment's format, language and scene, and `feedbackText` — the comments as notes (a pin's place in words: "top right"). Approved → into the chat of the approved variant at step 2 (a revision of its preview); rebuild → into "What should change" to rework all three directions. "Mark resolved" sets `state='resolved'` with a note (`/api/studio/campaigns/:id/comments/resolve`); resolved comments leave the notes.
- **The final to the client.** "Send the final…" in the banner while the request is `in_production` (`public/send-final.js`). `finalOf` takes the approved variant's final and refuses it when it is missing, stale, has a bad path, or lacks a format, language or length the client asked for; the title defaults to the one the client approved in the last round. `sendFinal` → `send_final` with the dashboard's `{final:{id,title,entryId,path,kind,formats,langs,lengths}}`. `delivered` ends the campaign.
- **Exports.** `export.mjs`: for the latest final delivery of each campaign, a video per format × language × length (mp4, H.264, 30 fps) and a still per format × language (png; posters: stills only), the dashboard's `expectedExports`. `render.mjs` draws them from the final's page on the preview origin with `renderFrame(t)` (headless Chrome, native size) and encodes with ffmpeg (`FORMA_FFMPEG`, else the `ffmpeg-static` package, else `ffmpeg` on PATH); stills show the poster, a third into a loop, or a story's end hold. Files go to R2 `deliveries/<id>/exports/<format>_<lang>_<length>s.mp4|_still.png`; rows in `delivery_exports` go `pending` first, then `ready` or `failed`. A worker started by `registerStudioRoutes` runs one export at a time: right after "Send the final", and every minute for finals with files missing (sent while Forma was off; left pending; failed, retried twice per run). `FORMA_EXPORTS=0` turns it off. For now it runs where Forma runs; it moves to the cloud with Forma.
- **Check after every build (rounds 5–7).** `checkBuild` / `afterBuild` in campaigns.mjs run on the server after every preview, final and revision (not in demo; `FORMA_CHECK=0` turns it off): frames rendered without a model (`renderSheets`), browser errors, flat frames, pure #00FF00 left in a frame, and the first frame always looked at. Stored on the entry as `output.check`. Hard problems (`hardProblems`: script/security/WebGL errors, failed loads, flat or green frames) start one revision on their own after the build's run ends (`startAutoFix`, message from `fixMessage`; never for a fix itself, `setup.review.autoFix === false` turns it off). The UI waits for that fix, then the art director looks; the look and revisions reuse the check's frames (revisions get them as "frames" to open).
- **Runtime (v2) for review and export.** `syncVideo` seeks every paused frame exactly (the old 0.04 s threshold skipped every other frame at 30 fps). `drawAt` draws again after a clip's `seeked`. Creatives may take up to 2 min (review) / 4 min (export) to report ready. Every `<img>`, `<video>`, `<audio>` and `new Image()` asks for CORS (`withCors` in the markup, a runtime patch for code), because the page's sandbox origin taints canvases otherwise. `FORMA.pixelRatio`: `?pr=`, else 2 on a real GPU and 1 on software WebGL, capped at 4096 px; 3D sets `renderer.setPixelRatio(FORMA.pixelRatio)`.
- **Video tool.** H3 Max takes one keyframe (first or last frame, refused together before any request). Only a clip that comes back uses the budget; three failures end video for the build. A clip is required when the approved direction makes a moment as video or its plan has a move pictures cannot make (time passing, a gesture, liquid, people moving); prompts name the action with tempo and count, the signs of time, "locked-off camera", "screen stays #00FF00".
- **Script step.** `usedIdeasForBrand`: the theme, idea and chosen pictures of the brand's earlier campaigns go as `used_ideas` with a fresh script ("do not repeat"). Revisions: sizes changed by a visible amount and said as numbers; a revision cannot add a line of text (the error says to add it in step 1).
- **Client context everywhere.** Campaign cards on a brand page carry a badge with the client's status ("Client · our move · …" when it is the studio's turn), from `/api/studio/campaign-statuses` (the inbox, keyed by Forma campaign id). The questionnaire and campaign pages in Clients show a timeline from `client_events` (`timeline()` in studio.mjs). The dashboard no longer has a studio simulator: every studio action is Forma's, and the dashboard refuses the studio actor.
