# Forma в облаке: Supabase + Cloudflare R2

Пошаговая инструкция: как выгрузить все текущие данные в облако, переключить Forma на общее хранилище и подключить коллегу.

После переключения:
- **история, кампании, проекты и индекс файлов** хранятся в Supabase (Postgres);
- **все файлы** — материалы, картинки, видео, HTML креативов и журналы сборок — лежат в Cloudflare R2;
- **каждый запускает Forma у себя локально,** но видит общие кампании и запуски.

> Названия пунктов в панелях Supabase и Cloudflare иногда меняются. Если пункт называется чуть иначе, ищите по смыслу.

---

## 1. Что понадобится

- Аккаунт **Supabase**: новый проект, регион поближе к Белграду, например Frankfurt (eu-central-1).
- Аккаунт **Cloudflare** с включённым **R2**. Для включения Cloudflare может попросить привязать карту, даже на бесплатном объёме.
- **Node.js 22.9+** и уже работающая локальная Forma: `npm ci` выполнен.
- 10–15 минут. Сама выгрузка текущих данных (около 125 МБ) занимает несколько минут и зависит от скорости интернета.

---

## 2. Supabase: база

1. Создайте проект. Пароль базы, который просит Supabase, сохраните в менеджер паролей: он понадобится в пункте 3.
2. Скопируйте:
   - **Project URL** вида `https://<ref>.supabase.co`. Он есть на главной странице проекта (кнопка **Connect**) или в **Project Settings → Data API**. Часть `<ref>` понадобится ниже.
   - **Ключ с правами service_role** из **Project Settings → API Keys**. Подойдёт **secret key** (начинается с `sb_secret_`) или классический **service_role** с вкладки **Legacy API Keys**.
   - Публичный ключ (anon / publishable) **не нужен**.
3. В терминале, в папке проекта Forma, выполните по одной команде:
   ```bash
   npx supabase login
   ```
   Откроет браузер и выдаст CLI токен доступа.
   ```bash
   npx supabase link --project-ref <ref>
   ```
   `<ref>` — из Project URL. Пароль базы CLI спросит здесь или на `db push`; его можно передать и флагом `--password`.
   ```bash
   npx supabase db push --remote --dry-run
   ```
   Покажет, какие миграции будут применены. Ничего не меняет.
   ```bash
   npx supabase db push --remote
   ```
   Создаёт таблицы в вашем проекте.

   `db push` применяет два файла: `20261116000001_forma_init.sql` (таблицы, индексы, RLS) и `20261116000002_forma_rpc.sql` (функции для безопасного обновления кампаний и цепочек правок).

   > **Флаг `--remote` обязателен.** С версии CLI 3 команда без него пытается писать в локальную базу (Docker) и падает с `ECONNREFUSED 127.0.0.1:54322`.
   >
   > Если CLI ругается на `supabase/config.toml` (например, `[inbucket] … is no longer supported`), значит, в файле остались секции от старого шаблона. Forma нужна только строка `project_id = "forma"`.
   >
   > Комментарии `# …` не вставляйте в одну строку с командой: в zsh на macOS они по умолчанию не считаются комментариями и уходят в команду как лишние аргументы.
4. Проверка: в Supabase откройте **SQL Editor** и выполните
   ```sql
   select * from schema_meta;
   ```
   Должна вернуться строка `forma_schema | 1`. Если её нет, сервер в облачном режиме не запустится и напишет «База Supabase не подготовлена».

## 3. Cloudflare R2: файлы

1. **R2 Object Storage → Create bucket.**
   - Имя: `forma`. Если выберете другое, укажите его в `R2_BUCKET`.
   - Location: Automatic.
   - **Public access не включайте.** Бакет должен быть закрытым: Forma сама раздаёт файлы через локальный сервер. CORS тоже не нужен.
2. **R2 → Manage API Tokens → Create API token.**
   - Permissions: **Object Read & Write**.
   - Specify bucket(s): только **forma**.
   - После создания Cloudflare один раз покажет **Access Key ID** и **Secret Access Key**. Сразу сохраните оба.
3. **Account ID** — это поддомен в S3-адресе, который показан там же: `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`. Его же видно на главной странице R2.

## 4. `.env`

Добавьте в `.env` (образец есть в `.env.example`):
```bash
# Хранилище: file — локальная папка data/, supabase — общее облако
# пока оставьте file; переключим на шаге 6
FORMA_STORE=file
# ваше имя: так подписываются ваши запуски и правки
FORMA_AUTHOR=Дмитрий

SUPABASE_URL=https://<ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...

R2_ACCOUNT_ID=<account id>
R2_ACCESS_KEY_ID=<access key id>
R2_SECRET_ACCESS_KEY=<secret access key>
R2_BUCKET=forma

# Необязательно: где держать локальный кэш файлов в облачном режиме (по умолчанию DATA_DIR / data)
# CACHE_DIR=
```

**Важно:**
- `.env` **никогда не коммитится**: он уже в `.gitignore`. Не отправляйте его в чатах.
- Коллеге передавайте значения через менеджер паролей (общий сейф 1Password, Bitwarden и т.п.).
- Ключ service_role даёт полный доступ к базе, а ключ R2 — ко всем файлам.

## 5. Выгрузка текущих данных

Выгрузку делает тот, у кого лежат данные, то есть вы. Коллеге этот шаг не нужен.

1. **Остановите сервер Forma** (Ctrl+C), чтобы во время копирования не появлялись новые сборки.
2. **Сделайте резервную копию** папки данных, на всякий случай:
   ```bash
   cp -R data data-backup-$(date +%Y%m%d)
   ```
3. **Пробный прогон**: ничего не меняет, только проверяет связь и показывает план.
   ```bash
   npm run cloud:migrate
   ```
   Скрипт покажет:
   - число проектов, файлов (по типам) и записей истории;
   - сколько файлов будет загружено и сколько уже лежит в R2;
   - сколько записей будет записано;
   - найденные стилевые копии кампаний, если есть;
   - файлы, на которые не ссылается ни одна запись (они тоже выгрузятся).
   На момент написания у вас 19 проектов, 554 файла (≈123 МБ) и 38 записей.
4. **Выгрузка:**
   ```bash
   npm run cloud:migrate -- --apply
   ```
   Если раньше вы создавали «копии» кампаний ради нового стиля и хотите склеить их в варианты стиля одной кампании, добавьте флаг:
   ```bash
   npm run cloud:migrate -- --apply --merge-style-forks
   ```
   Склеенные копии не удаляются. Они помечаются как `merged` и пропадают из списка кампаний, а их стили появляются переключателем «Стиль» в исходной кампании. Пробный прогон с этим флагом заранее покажет, что с чем склеится.
5. **Что делает скрипт:**
   1. Регистрирует проекты.
   2. Загружает файлы в R2 (по 4 параллельно, с повторами при сбоях) и заполняет индекс файлов.
   3. Переносит историю: старые кампании переводит на варианты стилей, журналы кладёт в R2, остальное пишет в Supabase.
   4. Проверяет результат: количество записей совпадает; каждый креатив есть в R2; контрольные суммы 10 случайных файлов совпадают; ссылки кампаний на шаги ведут на существующие записи; цепочки правок собираются.
6. **Отчёт** — `data/migration-report.json`: счётчики, объём, ошибки и план склейки.
7. **Если что-то упало** (сеть, лимиты), просто запустите ту же команду ещё раз. Всё, что уже загружено и не изменилось, будет пропущено. Скрипт **никогда не удаляет и не меняет** локальные файлы.

## 6. Переключение на облако

1. В `.env`: `FORMA_STORE=supabase`.
2. `npm start`.
3. Проверьте:
   - в шапке вместо «Локальный стенд» написано **«Облако · Дмитрий»** с зелёной точкой. Красная точка означает ошибку подключения, текст ошибки в подсказке;
   - **История** показывает те же записи, что и раньше: 38, или меньше в списке кампаний, если были склейки;
   - открывается старый креатив из истории. Его файлы подтянутся из R2 в локальный кэш при первом открытии;
   - открывается кампания, работают переключатели формата, языка, длины и «Стиль»;
   - проходит **тестовая кампания** целиком в режиме «Тестовый шаблон» (без токенов): сценарий → превью → видео;
   - коллега после подключения (шаг 7) видит эту кампанию, а пока она собирается, у него в шапке светится «Идёт: 1».
4. Локальная папка `data/` остаётся как есть: это резервная копия на момент выгрузки и одновременно кэш.

## 7. Подключение коллеги

1. Получить код проекта: склонировать репозиторий или скопировать папку **без** `data/`, `node_modules/` и `.env`.
2. Node.js 22.9+, затем в папке проекта:
   ```bash
   npm ci
   cp .env.example .env
   ```
3. В `.env`:
   - **общие значения:** `FORMA_STORE=supabase`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`;
   - **своё:** `FORMA_AUTHOR=<имя>`, а также свой `ANTHROPIC_API_KEY` или вход по подписке Claude (`npm run claude:login`) и при желании свой `OPENROUTER_API_KEY`. Генерации списываются с ключа того, кто запускает.
4. `npm start` → http://127.0.0.1:4317. При первом открытии проекта его файлы скачаются в локальный кэш, дальше всё работает так же быстро, как раньше.

Коллеге **не нужно** запускать `supabase db push` и `cloud:migrate`: база уже подготовлена и данные уже выгружены.

## 8. Как это устроено

- **Где что лежит.** Supabase хранит «что и когда»: записи истории, кампании и их варианты стилей, проекты, список файлов, запуски. R2 хранит сами файлы и журналы. Путь файла в R2 повторяет локальную структуру (`projects/<проект>/assets/...`, `projects/<проект>/<id>.html`), поэтому все ссылки на креативы остались прежними.
- **Локальный кэш.** Папка `data/` (или `CACHE_DIR`) — копия того, что вы открывали. Если в кэше нет нужного файла, предпросмотр сам подтягивает его из R2.
- **Синхронизация:**
  - перед каждой сборкой модель получает свежую копию всех материалов проекта;
  - после сборки новые файлы (картинки, видео, HTML, вложения из чата) загружаются в R2;
  - запись в истории появляется **только после** загрузки файлов, поэтому коллега никогда не увидит креатив с недостающими картинками.
- **Живые запуски.** Пока идёт сборка, её журнал раз в секунду пишется в базу. Индикатор «Идёт: N» в шапке показывает чужие запуски; по клику открывается кампания, и журнал запуска виден в реальном времени (без черновика превью).
- **Блокировки.** В одной кампании одновременно идёт только один шаг. Если коллега уже запустил шаг, вы увидите «Дождитесь окончания текущего шага (запущен …)». Если процесс оборвался (закрыли ноутбук), блокировка снимается сама через 2 минуты.
- **Конфликты.** Если вы оба одновременно меняете одну кампанию, второй получит «Кампанию только что изменил … — обновите страницу». Чужие изменения не затираются молча. Открытая кампания сама подхватывает изменения коллеги, история обновляется раз в 15 секунд.
- **Авторы.** У каждой записи есть автор. В истории есть фильтр «Все · Мои · Коллег».

## 9. Откат

- **Вернуться на локальный режим:** `FORMA_STORE=file` и перезапуск. Forma снова работает на нетронутой локальной папке `data/` в состоянии на момент выгрузки.
- **Всё, что сделано уже в облаке, есть только в облаке.** Чтобы забрать его локально, используйте:
  ```bash
  npm run cloud:pull -- --out ./data-from-cloud
  FORMA_STORE=file DATA_DIR=./data-from-cloud npm start
  ```
  `cloud:pull` скачивает все записи (с журналами) и все файлы в **новую** папку. В непустую папку он писать отказывается, так что случайно затереть данные нельзя.

## 10. Стоимость и лимиты

- **Объём сейчас:** около 123 МБ файлов в R2 и меньше 1 МБ записей в базе (журналы тоже лежат в R2).
- **Supabase:**
  - база растёт медленно: записи истории — это небольшие JSON;
  - на бесплатном тарифе проекты могут приостанавливаться при долгой неактивности; проверьте текущие условия в тарифах Supabase.
- **R2:**
  - плата за исходящий трафик не берётся, поэтому скачивание файлов коллегой ничего не стоит;
  - тарифицируются хранение и число операций сверх бесплатного объёма; при ваших объёмах это копейки или ноль;
  - актуальные цены — на странице тарифов R2.
- **Генерации** (Claude, OpenRouter) оплачивает тот, чей ключ в `.env`. Стоимость каждого шага по-прежнему видна в журнале и истории.

## 11. Безопасность

- **Ключи только в `.env` на сервере.** Ключ service_role и ключи R2 живут только в `.env` локального сервера, в браузер они не попадают. Доступ к таблицам для всех остальных закрыт политиками RLS: без ключа service_role прочитать базу нельзя.
- **Бакет R2 закрытый.** Публичных ссылок на файлы нет.
- **Если ключ утёк:**
  - **Supabase:** Project Settings → API Keys. Создайте новый secret key и удалите старый. Для legacy service_role нужно сменить JWT secret, и тогда сменятся все legacy-ключи.
  - **Cloudflare:** R2 → Manage API Tokens. Удалите токен и создайте новый с теми же правами.
  - Обновите `.env` у себя и у коллеги, затем перезапустите сервер.
- **Работа только локально.** Forma по-прежнему рассчитана на запуск на localhost. Не открывайте порты 4317 и 4318 наружу: авторизации в приложении нет.
